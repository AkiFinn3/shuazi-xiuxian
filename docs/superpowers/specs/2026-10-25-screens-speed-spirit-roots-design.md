# 多界面导航、战斗倍速与灵根系统设计

- 日期：2026-10-25
- 状态：待用户评审
- 项目：修仙挂机游戏（零构建原生 JS + Canvas）
- 目标版本：下一次功能更新

## 1. 背景与目标

当前游戏把战斗、装备、洞府、宗门、法宝、秘境、仙缘都挤在战斗页的左右侧栏里，移动端依赖抽屉和底部面板切换。功能继续增加后，侧栏空间不足，入口层级也不清晰。

本次更新要完成四件事：

1. 增加常驻导航，把每个功能拆成独立界面；原战斗页的桌面三栏布局保持不变。
2. 增加 1/2/3 倍战斗速度，随境界解锁。
3. 筑基后自动测灵根，加入五行灵根与天灵根体系。
4. 不同灵根提供属性加成和战斗触发特效，并配套元素颜色、粒子与文字反馈。

核心原则：战斗逻辑、境界成长、装备掉落和现有存档继续可用；新增系统只做增量，不重写战斗循环，不更换存档 key。

## 2. 非目标

- 不做五行克制/抗性矩阵，本次只做属性加成与触发效果。
- 不做灵根升级、洗练等级、灵根装备等延伸养成。
- 不重做战斗场景美术，不新增外部图片资源，特效全部用现有 Canvas FX 与 CSS 完成。
- 不做云存档、账号系统或后端。
- 不调整现有境界门槛、经验曲线、掉落率和装备词缀池。
- 不把固定 60Hz 循环改成可变帧循环。
- 不做页面切换动画的大规模重构；只保证切换稳定、状态不丢。

## 3. 方案选择

### 3.1 备选方案

**方案 A：屏幕路由层，保留战斗页（推荐）**

在现有 `.main` 外增加一个屏幕容器和导航层。战斗页 DOM 原样保留，其他界面按需挂载；复用现有面板渲染函数，离开战斗页时卸载侧栏内容，避免重复 DOM id。后台战斗继续运行。

- 优点：改动可控，战斗页零视觉回归；现有渲染逻辑可逐步迁移；移动端只替换底部入口，不重写战场。
- 缺点：需要先治理现有渲染函数对全局 id 的依赖；全屏页与战斗侧栏会短暂并存，必须明确卸载时机。

**方案 B：全量 SPA 重构**

把左右面板、战斗、所有功能都拆成组件和独立路由，统一状态订阅，重写样式与渲染。

- 优点：长期结构最干净。
- 缺点：改动面过大，战斗、移动端布局、事件绑定都要重测，回归风险高，不适合本次功能增量。

**方案 C：全屏弹窗承载各功能**

每个功能点开一个全屏 modal，战斗页完全不动。

- 优点：实现最快。
- 缺点：没有真正的常驻导航，后台切换体验差，移动端弹窗叠弹窗，和“独立界面”的目标不符。

### 3.2 结论

采用方案 A。新增 `js/ui/screens.js` 作为屏幕路由，新增 `js/ui/nav.js` 渲染桌面导航与移动底栏。战斗页内部结构保持原样，其他页面复用现有渲染函数并做容器化改造。

设置继续使用顶栏齿轮打开的 modal，不占导航位。

### 4.2 桌面导航

- 顶栏下方增加左侧竖向导航栏，宽度 64px；每一项为图标 + 两字标签。
- 导航栏常驻，9 个界面全部可见；当前页高亮。
- 战斗页内容区仍是原来的 `232px | 战场 | 300px` 三栏，不改内部结构。
- 其他页面占据导航栏右侧的完整内容区，页面内容最大宽度 1180px，居中，两侧留白。
- 视口宽度 ≤900px 或高度 ≤560px 时切换为移动布局，不显示桌面导航栏。

### 4.3 移动导航

- 底部常驻 6 个入口：战斗、角色、背包、洞府、宗门、更多。
- “更多”打开底部弹层，列出：灵田、秘境、法宝、仙缘、设置。
- 底部导航适配 `env(safe-area-inset-bottom)`；横屏高度紧张时压缩为图标 + 10px 标签。
- 原战斗页的 `#tabbar`、抽屉和遮罩逻辑退役，由全局导航取代。战斗页在移动端保留战场与技能栏，侧栏功能通过新界面进入。
- 原来的旋转提示、物品详情底部弹层、modal 逻辑继续保留。

### 4.4 页面容器与路由

`index.html` 调整为：

```html
<div class="app-body">
  <nav class="nav-rail" id="navRail"></nav>
  <div class="screen-root" id="screenRoot">
    <section class="screen" data-screen="battle" id="battleScreen">
      <!-- 现有 .main 与技能栏原样放在这里 -->
    </section>
    <!-- 其他 screen 按需挂载 -->
  </div>
</div>
<nav class="nav-mobile" id="navMobile"></nav>
<div class="sheet-root" id="moreSheet" hidden></div>
```

路由接口：

```js
// js/ui/screens.js
export function initScreens(game) {}
export function showScreen(key) {}
export function currentScreen() {}
export function markScreenDirty(key) {}
export function refreshActiveScreen() {}
```

切换规则：

1. 离开战斗页时，清空 `#leftPanel` 与 `#rightPanel` 的 `innerHTML`，避免全屏页和隐藏侧栏出现重复 DOM id；返回战斗页时调用 `markPanelsDirty('both')` 并立即刷新。
2. 离开任意非战斗页时，清空该页 `innerHTML`，移除其事件监听；下次进入重新渲染。
3. 只保留一个非战斗页挂载。切页时先卸载旧页，再挂载新页。
4. 切到战斗页后立即重绘一次 Canvas，避免隐藏期间画面停留在旧帧。
5. 页面 key 只存在内存，刷新后默认回到战斗页；不写入存档。

### 4.5 后台战斗

- 切到非战斗页时，`Game.update` 继续更新战斗、敌人、FX、任务击杀计数。
- 非战斗页激活时跳过 Canvas 绘制与战斗 HUD 的 DOM 更新，返回战斗页时立即补一次绘制。
- 战斗页的桌面左右侧栏只在战斗页挂载；后台战斗不依赖侧栏 DOM。
- 技能快捷键 1/2/3 只在战斗页生效；Space 暂停保持全局可用但不在输入框内触发。

### 4.6 现有渲染函数的容器化

现有面板渲染函数大量按容器 `body` 生成 HTML，但部分查询可能使用 `document.getElementById`。迁移要求：

- 所有渲染函数改为只在传入的根容器内查询：`root.querySelector(...)`。
- 事件监听绑定在根容器或具体元素上；页面卸载时整段 DOM 删除即可释放。
- 实时刷新沿用现有 2Hz 节奏；刷新前保存页面滚动位置，若焦点在输入框/下拉框内则跳过本次重渲染。
- 状态变更通过 `markScreenDirty(key)` 标记，活动页在下一次刷新 tick 重渲染；隐藏页不渲染。

## 5. 战斗倍速

### 5.1 解锁与持久化

- 存档字段：`state.settings.speed`，取值 1/2/3，默认 1。
- 1 倍始终可用。
- 2 倍在炼气圆满解锁：`realm === 0 && stage >= 3`。
- 3 倍在筑基初期解锁：`realm >= 1`。
- 在 `state.js` 提供 `maxSpeed(state)`，加载、导入、升级后都用它钳制已保存速度。
- 解锁时记录一次日志与 toast；用 `Game._lastMaxSpeed` 对比，避免重复提示。刷新页面不重复提示。

### 5.2 时间缩放范围

`Game.update(realDt)` 中拆分两种时间：

- 战斗时间：`battleDt = realDt * speed`，用于战斗更新、敌人移动/攻击、技能冷却、灵根触发冷却、敌人状态、FX 动画。
- 真实时间：用于游戏时长统计、自动存档、随机事件、炼丹/灵田计时、HUD 刷新、面板实时刷新、离线统计、提示气泡。

这样倍速只加速战斗模拟，不加速炼丹、灵田和随机事件，避免额外资源漏洞。暂停时战斗时间不推进。

### 5.3 界面

- 桌面与移动战斗页的技能栏左侧增加一个速度按钮，显示 `×1` / `×2` / `×3`。
- 点击在已解锁档位间循环切换；未解锁档位不进入循环。
- 设置 modal 增加“战斗速度”一行，三个按钮，未解锁按钮显示条件文案：
  - 2 倍：炼气圆满解锁
  - 3 倍：筑基初期解锁
- 切换后立即写入存档并刷新按钮状态；后台战斗按新速度继续。
- 按钮提供 `aria-label` 与 `title`，例如“战斗速度 2 倍，点击切换”。

## 6. 灵根系统

### 6.1 触发时机

- 新角色首次突破到筑基成功时，在渡劫成功结算后自动排队测灵根。
- 旧存档只要 `realm >= 1` 且没有有效灵根数据，加载后补测一次。
- 炼气期不测灵根；角色页显示“筑基后开启”。
- 测灵根 modal 不可取消，必须确认结果；结果在打开前就写入状态并保存，避免刷新重roll。
- 用排队机制等待现有 modal 关闭：若渡劫结果、离线报告、设置等 modal 仍打开，每 300ms 重试，直到 `#modalRoot` 为空再打开。防止 modal 叠加。
- 已存在有效灵根数据时不重复触发。

### 6.2 数据结构

```js
state.spiritRoots = {
  v: 1,
  testedAt: 1730000000000,
  heavenly: false,
  roots: [
    { elem: 'metal', grade: 0 }
  ]
}
```

- `elem`：`metal | wood | water | fire | earth`，对应金、木、水、火、土。
- `grade`：`0 | 1 | 2 | 3`，对应下品、中品、上品、天品。
- 普通灵根 1–5 种，元素不重复。
- 天灵根固定 1 种元素、天品，`heavenly: true`。
- 无效结构（空数组、重复元素、非法枚举、天灵根数量不为 1 等）在 `normalizeState` 中置为 `null`，满足境界条件时补测。

### 6.3 随机规则

```js
export function rollSpiritRoots(rng = Math.random) {
  if (rng() < 0.01) {
    const elem = pick(ELEMENTS, rng);
    return {
      v: 1,
      testedAt: Date.now(),
      heavenly: true,
      roots: [{ elem, grade: 3 }],
    };
  }

  const count = weightedPick([1, 2, 3, 4, 5], [40, 30, 18, 9, 3], rng);
  const elems = shuffle(ELEMENTS, rng).slice(0, count);
  const roots = elems.map((elem) => ({
    elem,
    grade: weightedPick([0, 1, 2, 3], [60, 28, 10, 2], rng),
  }));

  return { v: 1, testedAt: Date.now(), heavenly: false, roots };
}
```

- 天灵根总概率 1%。
- 五行数量概率：1 种 40%、2 种 30%、3 种 18%、4 种 9%、5 种 3%。
- 每种灵根品阶概率：下品 60%、中品 28%、上品 10%、天品 2%。
- 天灵根元素在五系中等概率随机。
- 随机函数接受注入的 RNG，方便用固定序列做分支测试。

### 6.4 品阶与数值

品阶属性倍率：

| 品阶 | 索引 | 属性倍率 |
| --- | --- | --- |
| 下品 | 0 | 1.0 |
| 中品 | 1 | 1.8 |
| 上品 | 2 | 3.0 |
| 天品 | 3 | 5.0 |

每个元素的下品基础属性（实际值 = 基础值 × 品阶倍率）：

| 元素 | 属性加成 | 战斗效果 |
| --- | --- | --- |
| 金 | 攻击 +4%，暴击 +2%，爆伤 +6%，穿透 +2% | 裂金 |
| 木 | 生命 +5%，吸血 +1.5% | 回春 |
| 水 | 攻速 +0.06，防御 +4% | 寒霜 |
| 火 | 攻击 +5% | 灼烧 |
| 土 | 生命 +6%，防御 +6% | 震地 |

天灵根在上述结果上再乘 1.4 作为属性倍率。示例：天灵根·金 = 攻击 +28%、暴击 +14%、爆伤 +42%、穿透 +14%。

多个普通灵根的加成按元素逐项相加。结算顺序放在装备、法宝、仙缘天赋之后、最终取整之前，避免乘法顺序歧义。

### 6.5 战斗触发

`g` 为品阶索引 0–3。每个效果独立冷却，冷却使用战斗时间，倍速与暂停同步生效。

| 元素 | 效果名 | 触发与数值 | 冷却 |
| --- | --- | --- | --- |
| 金 | 裂金 | 命中时 `20 + 4g`% 概率追加 `50 × (1 + 0.2g)`% 攻击伤害，按目标防御的 60% 计算减伤 | 3 秒 |
| 木 | 回春 | 每 8 秒回复 `1.5 + 0.5g`% 最大生命；击杀额外回复 1% 最大生命 | 8 秒 |
| 水 | 寒霜 | 命中时 `18 + 4g`% 概率使目标减速 35%，持续 2 秒 | 5 秒 |
| 火 | 灼烧 | 命中时 `20 + 4g`% 概率点燃 3 秒，每秒造成 `18 + 4g`% 攻击伤害 | 4 秒 |
| 土 | 震地 | 命中时 `12 + 3g`% 概率眩晕 0.7 秒，并获得 `3 + g`% 最大生命护盾 | 8 秒 |

天灵根强化：

- 效果伤害/治疗/护盾数值 ×1.5。
- 命中类效果触发概率 +8 个百分点，上限 50%。
- 水：减速 50%，持续 2.5 秒。
- 火：灼烧持续 4 秒。
- 土：眩晕 1.0 秒，护盾按 1.5 倍结算。
- 金：追加伤害按 1.5 倍结算。
- 木：回复量按 1.5 倍结算。

通用规则：

- 每次英雄造成伤害最多触发 1 个命中类灵根效果，按灵根数组顺序判定，避免 5 灵根同帧爆发。
- 回春是独立周期效果，不占命中触发次数。
- 灵根追加伤害、灼烧伤害不再触发其他灵根，不吸血，不递归。
- 灵根伤害击杀敌人时，正常走击杀结算：掉落、任务计数、Boss 判定、木系击杀回血。
- Boss 的减速、眩晕持续时间 ×0.5；灼烧与追加伤害不打折。
- 同种效果再次触发时刷新持续时间；护盾取最大值，不叠加。
- 敌人死亡时清空减速、眩晕、灼烧状态；新一波敌人不继承。

### 6.6 状态与伤害接入点

战斗增加统一的伤害结算入口，避免基础攻击、技能、灵根、灼烧各自复制死亡与掉落逻辑：

- 基础攻击与技能造成伤害后，调用 `_afterHeroDamage(target, damageInfo)` 判定灵根触发。
- 灵根追加伤害、灼烧 tick 走 `_applyDamage(target, amount, opts)`；该函数负责扣血、闪白、飘字，并在死亡时调用 `_killEnemy`。
- 敌人状态字段：`slowUntil`、`slowPct`、`stunUntil`、`burn`（`until`、`dps`、`nextTick`）。
- 敌人移动速度与攻击冷却按减速比例降低；眩晕期间不移动、不攻击，动画暂停。
- 英雄护盾字段：`shield`、`shieldUntil`；敌人伤害先扣护盾，再扣生命。护盾到期清零。
- 回春与护盾飘字、粒子复用现有 FX。
- 灼烧每 0.5 秒结算一次伤害，使用元素色飘字；灼烧可以击杀敌人。

元素主色：

| 元素 | 颜色 |
| --- | --- |
| 金 | `#e8d98a` |
| 木 | `#6fd68a` |
| 水 | `#6fb8ff` |
| 火 | `#ff8a5c` |
| 土 | `#c9a46a` |

- 木属性：英雄身上绿色光点 + 绿色治疗数字 + “回春”飘字。
- 水属性：目标脚下蓝色圆环 + “寒霜”飘字，减速期间目标移动拖影。
- 火属性：目标身上橙色火星 + 灼烧 tick 数字 + “灼烧”飘字。

### 6.8 角色页灵根区

- 角色页新增“灵根”区块，位于属性之后、装备之前。
- 未筑基：显示“灵根未测，筑基后开启”。
- 已测灵根：每系一张卡片，显示元素名、品阶、属性加成、战斗效果说明；卡片边框使用元素色。
- 天灵根：单张金色卡片，显示“天灵根”称号、强化后的属性与效果说明。
- 卡片文案由同一份数据表生成，避免 UI 与战斗数值不一致。

### 6.9 测灵根弹窗

- 标题“测灵根”，不可点击遮罩关闭。
- 第一阶段：五颗元素光球依次亮起，约 1.2 秒。
- 第二阶段：展示结果卡片；普通灵根按数量排列，天灵根触发金色闪光与“天灵根”大字。
- 底部“确认”按钮关闭弹窗；结果已提前保存。
- 关闭后写入日志摘要，例如“测灵根：金（上品）、火（中品）”。
- 天灵根额外写入一条“天灵根现世”日志。

### 6.10 洗髓丹重测

- 洗髓丹保留“重铸装备词缀”用途，并在已测灵根且 `realm >= 1` 时增加“重测灵根”选项。
- 使用洗髓丹时先弹选择框：
  - 重测灵根：重新执行完整灵根随机，可出天灵根；确认后覆盖旧灵根。
  - 重铸装备词缀：沿用现有逻辑。
  - 取消：不消耗丹药。
- 丹药在玩家确认选项后才扣除；取消或关闭选择框不扣。
- 重测结果弹出简化版结果面板，可再次查看属性与效果。
- 更新丹方描述，明确两种用途。
- 重测使用与初始测灵根相同的概率和 RNG 接口。

## 7. 存档与兼容

### 7.1 版本

- `SAVE_VERSION` 从 1 升到 2。
- 存档 key 保持 `shuazi_xiuxian_save_v1`，避免旧存档失联。
- 旧 v1 存档通过 `normalizeState` 补字段后继续使用。

### 7.2 新增字段

- `state.spiritRoots`：默认 `null`。
- `state.settings.speed`：默认 `1`。

### 7.3 迁移规则

- `createState` 写入上述默认值。
- `normalizeState`：
  - 校验 `spiritRoots` 结构；非法则置 `null`。
  - 校验 `settings.speed` 为 1/2/3，否则置 1；再按 `maxSpeed(state)` 钳制。
  - 保留现有 `pendingRealm` 清理逻辑。
- 加载、导入、飞升重置后都检查：`realm >= 1 && !spiritRoots` 时排队补测。
- 导出存档包含灵根与速度；导入旧存档后同样触发补测。
- 飞升不重置灵根；灵根属于角色本体。
- 离线收益不使用倍速，不改变灵根。

## 8. 性能与稳定性

- 后台战斗只跑逻辑，不绘制 Canvas；返回战斗页立即补绘。
- 全屏页只在激活时挂载，实时页按 2Hz 刷新，不在 60Hz 循环里重建 DOM。
- 实时刷新保留滚动位置；输入框聚焦时跳过重渲染。
- 灵根触发与灼烧粒子数量受限，避免 5 灵根同屏时 FX 爆量。
- 战斗时钟统一使用累加 `clock`，所有冷却、状态持续时间都以战斗时间计算，倍速与暂停天然一致。
- 所有伤害路径统一走 `_applyDamage`，避免灵根击杀绕过掉落与任务计数。

## 12. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 全屏页与战斗侧栏重复 DOM id、事件串扰 | 离开战斗页清空侧栏；渲染函数改为容器内查询；切页卸载旧 DOM |
| 实时页重渲染导致滚动跳动、输入丢失 | 刷新前保存 `scrollTop`；输入框聚焦时跳过刷新 |
| 后台战斗增加 CPU 占用 | 隐藏时跳过 Canvas 绘制；粒子限量；页面 2Hz 刷新 |
| 移动端新增底栏压缩战场高度 | 移除旧 tabbar/drawer 释放空间；横竖屏分别回归；技能栏置于底栏上方 |
| 灵根数值过强破坏平衡 | 下品基础值保守；数值集中在 `spirit_root.js`；上线前用筑基、金丹两个阶段实测 |
| 多灵根同帧触发导致卡顿与视觉混乱 | 每次伤害最多 1 个命中类触发；每个效果独立冷却；粒子上限 |
| 旧存档补测弹窗与现有 modal 冲突 | 排队等待 `#modalRoot` 清空；结果先保存再展示 |
| 倍速导致炼丹/灵田等计时被加速 | 明确拆分战斗时间与真实时间，只缩放战斗相关更新 |
| 灵根击杀绕过掉落/任务 | 所有伤害统一走 `_applyDamage` 与 `_killEnemy` |
| 速度字段被改坏或超出解锁 | `normalizeState` 校验并按 `maxSpeed(state)` 钳制 |
